# Аудит соответствия УГО для проектной Э3

**Дата:** 31.10.2026.  
**Статус:** первичная матрица геометрии и нумерации; ещё не является разрешением на замену символов в рабочей схеме.

## 1. Источники

- Локальная конверсия старой библиотеки `Device_GOST.lib` командой KiCad 10 `kicad-cli sym upgrade` в файл `Device_GOST.kicad_sym`.
- Публичный проект [KiCad-RU/kicad-symbols-gost](https://github.com/KiCad-RU/kicad-symbols-gost). README библиотеки описывает внутренние соглашения: шаг выводов распространённых компонентов 50 mil, размещение имён выводов внутри символа, размер текста имён/номеров выводов около 2 mm, длина выводов распространённых компонентов 3,8 mm. Это правила библиотеки, а не самостоятельное доказательство нормативного соответствия.
- Применимые стандарты по типам символов перечислены в [критериях приёмки Э3](acceptance_criteria.md).

Библиотека KiCad-RU в публичном репозитории выглядит как legacy-источник формата `.lib` и последний раз обновлялась в 2021 году. Поэтому для проекта используется локально конвертированная и проверенная копия, а не прямая зависимость от изменяемой внешней библиотеки. При добавлении в Git нужно сохранить исходный источник, лицензионные сведения, дату/commit и результат конвертации.

## 2. Первичная таблица контактов

Координаты указаны в локальной системе координат символа KiCad после конвертации. Углы — значения `(at x y angle)` из определения вывода. При вращении символа на листе координаты выводов должны быть пересчитаны; старые wire-координаты не сохраняются автоматически.

| Функция | Кандидат GOST symbol | Нумерация/геометрия GOST-кандидата | Сравнение с текущей системной библиотекой KiCad | Решение |
|---|---|---|---|---|
| Резистор | `Device_GOST:R` | 1: (-8.89, 0), 2: (8.89, 0) | `Device:R`: 1=(0, 3.81), 2=(0, -3.81). Нумерация совпадает, направление и координаты отличаются. | Кандидат. При переходе на горизонтальный УГО заново построить провода и поля. |
| Конденсатор неполярный | `Device_GOST:C` | 1: (0, 5.08, 270°), 2: (0, -5.08, 90°) | У системного `Device:C` координаты выводов совпадают по предварительной локальной проверке; визуальную форму отдельно сопоставить с ГОСТ 2.728-74. | Кандидат. Сохранить pin 1/2, перепроверить геометрию. |
| Конденсатор полярный | `Device_GOST:CP` | 1: (0, 5.08, 270°), 2: (0, -5.08, 90°) | У системного `Device:C_Polarized` координаты совпадают по предварительной локальной проверке; проверить знак полярности на графике и соответствие ГОСТ 2.728-74. | Кандидат. Полярность обязательно проверить визуально и по netlist. |
| Светодиод | `Device_GOST:HL_LED` | 1=K: (0, 8.89, 270°), 2=A: (0, -8.89, 90°) | Системный `Device:LED`: 1=K слева, 2=A справа, координаты ±3.81 mm. Pin mapping совпадает, геометрия существенно отличается. | Кандидат. Перестроить соединения и положение Reference/Value. |
| Диод | `Device_GOST:VD` | 1=K: (-6.35, 0), 2=A: (6.35, 0) | Системный `Device:D`: 1=K, 2=A, геометрические координаты отличаются. | Кандидат. Проверить графическую ориентацию катода и пересчитать провода. |
| NPN-транзистор | `Device_GOST:VT_NPN_BCE` | 1=B: (-8.89, 0), 2=C: (3.81, 8.89, 270°), 3=E: (3.81, -8.89, 90°) | `Transistor_BJT:Q_NPN_BCE`: соответствие pin 1=B, 2=C, 3=E подтверждено предварительно. | Кандидат. Не назначать корпус по обозначению УГО; физическую распиновку КТ3102Б подтверждать по конкретному datasheet. |
| Выключатель | `Device_GOST:SA_SPST_NO` | 1 слева (-7.62, 0), 2 справа (7.62, 0), нормально разомкнутый контакт | `Switch:SW_SPST`: нумерация и состояние NO совпадают. | Кандидат. Сопоставить графический знак с ГОСТ 2.755-87. |
| Таймер NE555 | Пока нет утверждённого GOST-кандидата | Нужно сформировать прямоугольный функциональный символ с точными выводами 1…8 и наименованиями функций | Текущий `Timer:NE555D` нельзя принимать автоматически как ЕСКД-оформление. | Не менять до отдельной сверки символа, datasheet и выбранного исполнения SOIC/DIP. |
| A1 / HA1 / XS1 | Универсальные разъёмы и внешние модули | Физическая распиновка A1 Joy-IT SEN-MQ4 V1 не подтверждена. HA1 и XS1 также требуют подтверждения конкретного исполнения. | Системные `Connector_Generic:Conn_01xNN` — технические абстракции, не окончательный внешний вид соединителя. | Оставить предварительными. Не объявлять pin number физической нумерацией разъёма. |

## 3. Правила принятия символа

Символ можно перенести в проектную библиотеку только после выполнения всех пунктов:

1. Проверить графическое обозначение по конкретной таблице/позиции применимого ГОСТ, а не по одному имени библиотеки.
2. Проверить число выводов, номера, электрические типы, имена и координаты по KiCad-определению и datasheet.
3. Сохранить исходный symbol ID и целевой symbol ID в таблице миграции.
4. Сформировать координатный список всех выводов до/после преобразования.
5. Пересчитать все wire endpoints и labels по новым координатам.
6. Экспортировать XML netlist и получить полный exact PASS. Проверять нужно все сети, весь component inventory, все выводы и NC.
7. Запустить ERC с активными категориями `four_way_junction`, `pin_not_connected`, `endpoint_off_grid`, `footprint_filter` и остальными правилами. Нельзя отключать правила для получения формального PASS.
8. Экспортировать SVG и проверить каждый символ в полном листе и крупном масштабе.

## 4. Обнаруженные риски

- Pin number совпадает не означает, что совпадают координаты вывода. Нельзя просто заменить `Device:R` на `Device_GOST:R` в строке `lib_id`.
- Значение symbol field (`NE555N`, `КТ3102Б`, номинал) само по себе не определяет корпус и физический pinout.
- Визуальное соответствие УГО стандарту требует сверки конкретного графического исполнения. Это не устанавливается только по результату ERC/netlist.
- Универсальные разъёмы и PWR_FLAG не должны маскироваться под окончательные физические компоненты в выпускном BOM.
- Третьестороннюю GOST-библиотеку следует проверить по лицензии, версии и происхождению перед коммитом в проект.

## 5. Следующая работа

1. Перенести локально конвертированные `.kicad_sym` и исходную legacy-библиотеку в проектную vendor-структуру с лицензией и hash/commit источника.
2. Проверить SVG-каталоги кандидатов и зафиксировать точные номера ГОСТ для резистора, конденсатора, LED, диода, транзистора и переключателя.
3. Создать проектную библиотеку символов, не изменяя пока текущую экспериментальную схему.
4. После утверждения библиотеки мигрировать символы по одному и выполнять полный netlist/ERC после каждого функционального блока.
