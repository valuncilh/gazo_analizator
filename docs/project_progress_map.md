## 1. Правила статусов

| Статус | Значение |
|---|---|
| **PASS** | Проверка завершена в явно указанном объёме. |
| **PARTIAL** | Результат есть, но остаются проверки или ограничения. |
| **BLOCKED** | Нет исходных данных, решения или доказательства, без которых следующий шаг небезопасен. |
| **NOT STARTED** | Работы ещё не выполнены. |
| **TBC** | Неопределённость, которую нельзя закрыть имеющимися материалами. |
| **HISTORICAL** | Старый вариант, не используется в текущей конструкции. |

## 5. Открытые блокеры и ограничения

| ID | Вопрос | Влияние |
|---|---|---|
| B1 | KT3102B draft footprint создан, но верхний вид содержит размер 1.2 mm, который ещё не сопоставлен координатам pad | Уточнить coordinate interpretation; не менять symbol map 1=B, 2=C, 3=E и не считать footprint fabrication-ready. |
| B2 | Для DA1 физический кандидат NE555P PDIP-8, а утверждённый символ NE555D имеет графику SOIC-8 | В отдельной реализации проверить соответствие pin numbers и физических функций, не менять approved E3. |
| B3 | Не установлена документально ориентация Molex pin 1 относительно VCC/DOUT/AOUT/GND A1. Полярность физического HA1 тоже не установлена | Сохранить TBC, не выдумывать кабельную распиновку или полярность. |
| B4 | Полный максимальный ток SEN-MQ4-V2 не опубликован | Бюджет 300 мА и выбор eFuse/PTC не объявлять доказанными. Физические измерения не входят в проект. |
| B5 | Параметры USB-C защиты E4 ещё не выбраны | Не фиксировать номинал защиты до обоснования по документированным входным данным. |
| B6 | Старый корпус FreeCAD рассчитан на прежнюю конфигурацию | Не использовать его как базу размеров для новой сборки без переработки. |
| B7 | Часть РПЗ/старых документов содержит прежние статусы V1/Amperka и иные CAD-артефакты | Синхронизировать и явно маркировать исторические материалы. |

## 6. Утверждённые климатические условия

Пользователь утвердил проектные условия окружающей среды:

- Температура: **+10…+35 °C**.
- Относительная влажность: **20–80 % без конденсации**.

Эти значения являются проектными условиями, а не гарантией характеристик MQ-4 или сертификатом изделия. На этапе P2 нужно документально проверить диапазоны всех выбранных компонентов. NE555P с указанным изготовителем диапазоном 0…+70 °C покрывает температурный интервал проекта. Совместимость остальных компонентов ещё проверяется.

## 7. Порядок обновления карты

1. После каждого закрытого контрольного результата обновлять статус здесь и в SVG-карте.
2. В `requirements/verification_matrix.md` обновлять критерии и доказательства, а не дублировать их в карте.
3. В инженерный журнал записывать дату, часовой пояс, конкретное действие, команды/инструменты, результат, ограничения и commit SHA.
4. После каждого логического изменения создавать отдельный небольшой commit в `analysis/vendor-behavioral-reconciliation` и проверять, что удалённая ветка получила этот commit.
5. Все действия выполнять только в единственной рабочей/default ветке. PR #4 закрыт без слияния и не входит в текущий маршрут.
6. Не запускать GitHub Actions/CI.
7. Не заявлять PASS для физических измерений, калибровки, сборки или пригодности газосигнализатора. Изготовление и лабораторные измерения не входят в объём текущего проекта. CAD-пересечения, расчёты, ERC/DRC и паспортные сверки фиксировать как отдельные виды доказательств.
