## Обязательные правила

1. Перед изменением проверить текущий HEAD и прочитать целевой файл.
2. Не использовать массовое добавление/удаление файлов без аудита.
3. Утверждённую E3, её XML-netlist и тег gost-e3-approved-2026-11-01 не изменять при редактуре документации.
4. Статусы APPROVED, VERIFIED, PRELIMINARY, BLOCKED и HISTORICAL применять только в пределах фактически выполненной проверки.
5. Не объявлять производственную готовность по наличию KiCad-файла. Для PCB нужны проверенные footprints, трассировка, ERC/DRC, 3D-проверка и производственные экспорты.
6. Не смешивать SPICE, расчётные допущения и аппаратные измерения.
7. Исторические материалы сохранять для прослеживаемости. Из основного маршрута чтения их исключать через навигацию и статусные предупреждения, а не удалять.
8. После каждого логически завершённого изменения создавать отдельный commit и проверять его присутствие в удалённой ветке.
