# Git policy проекта gazo_analizator

**Дата актуализации:** 02.11.2026  
**Единственная рабочая и default branch:** `analysis/vendor-behavioral-reconciliation`.

## 1. Рабочее правило

Все новые изменения, проверки, контрольные точки, инженерный журнал и карта прогресса ведутся только в `analysis/vendor-behavioral-reconciliation`. Не создавать параллельные ветки разработки.

GitHub API на дату проверки подтверждает указанную ветку как default branch. Коммиты, созданные через GitHub Contents API, сразу записываются в неё. Каждая логически завершённая операция получает отдельный осмысленный commit.

## 2. Защищённые артефакты

1. Утверждённая схема E3:
   `cad/project_modification/gost_e3_final/gazo_analizator_E3_GOST_itog.kicad_sch`.
2. Утверждённый XML-netlist:
   `cad/project_modification/gost_e3_final/reports/kicad10/netlist_current.xml`.
3. Базовая редакция `gost-e3-approved-2026-11-01`.

Эти артефакты нельзя редактировать в рамках назначения footprints, создания PCB реализации или оформления документации. Для реализации E3 всегда использовать отдельную проектную копию.

## 3. Порядок изменений

1. Перед изменением получить актуальную версию файла из единственной рабочей ветки.
2. Проверить, что изменение не затрагивает защищённые артефакты.
3. Изменять только конкретные необходимые файлы, не выполнять массовые операции без аудита.
4. Выполнить доступные source-level проверки и записать ограничения.
5. Создать отдельный commit с ясным сообщением.
6. Проверить, что commit доступен в `analysis/vendor-behavioral-reconciliation`.
7. Обновить инженерный журнал, матрицу верификации и карту прогресса, когда изменился их статус или доказательная база.

## 4. Pull requests

PR #4 закрыт без слияния и не является частью текущего маршрута разработки. Не переоткрывать его и не создавать заменяющий PR без прямого решения пользователя. Работу продолжать непосредственно в единственной рабочей ветке.

## 5. Границы достоверности

- **APPROVED** относится к зафиксированной версии схемы, а не к физической приёмке.
- **VERIFIED** указывать только для реально выполненного вида проверки.
- **PRELIMINARY / DRAFT / TBC / BLOCKED** сохранять до закрытия соответствующего доказательства.
- SPICE, паспортные сведения, KiCad ERC/DRC и CAD-проверки не подменяют друг друга.
- Физическое изготовление, закупка, сборка и лабораторные измерения исключены из текущего объёма.
- Не объявлять производственную готовность по наличию KiCad-файла или 3D-модели.
