# SPICE-моделирование сигнализатора газа

Журнал текущего состояния: [`checkpoint_2026-10-25.md`](checkpoint_2026-10-25.md).

## Первый этап: поведенческая модель

Файл `alarm_chain_behavioral.cir` моделирует цепочку:

`A1.S → U2 → DOUT' → R2 → VT1 → RESET DA1 → мигающий выход → HL1 / VT2 / HA1`.

В качестве симулятора выбран **ngspice**. Netlist самодостаточный и не требует внешних библиотек моделей. Сначала проверяем функциональную связность и ожидаемые тенденции. Позднее поведенческие блоки следует заменить моделями изготовителей и сравнить результаты.

### Установка и запуск

На CachyOS / Arch Linux установи ngspice из официального репозитория:

```sh
sudo pacman -S ngspice
```

Затем из корня репозитория запусти:

```sh
ngspice -b spice/alarm_chain_behavioral.cir
```

Модель запишет временные ряды в `spice/spice_chain_results.dat` и напечатает измеренные времена переключения, период выходных импульсов и пиковый ток источника. Для интерактивного просмотра запусти файл без флага `-b`, а команды `plot v(S) v(UREF)`, `plot v(DOUT) v(RESET)` и `plot v(OUT) v(CT)` вводи в консоли ngspice после расчёта. Если команды вывода уже были выполнены в пакетном режиме, повторно запусти анализ в интерактивном режиме.

Параметр `SOUND_ENABLE=1` включает звуковой канал и HL2. Для проверки без звука замени его значение на `0`. Параметр `C_TIMER=4.7u` сохраняет номинал C1 из исходных данных. Для отдельного сравнительного прогона можно установить `C_TIMER=47u`, не заменяя при этом исходное значение в документации.

## Ограничения модели

- **A1 / MQ-4.** Источник `VSENSE` создаёт синтетический аналоговый сигнал 0,30–4,50 В для проверки порога. Это не модель газового элемента и не калибровка напряжения в ppm.
- **U2 / TLV7041-Q1.** Поведенческий компаратор с открытым стоком и приближённым типовым гистерезисом. Это не официальная макромодель TI. TI публикует PSpice-модель TLV704x и модель TINA-TI для TLV7041-Q1 на странице продукта: https://www.ti.com/product/TLV7041-Q1. Следующим этапом следует получить исходный архив, проверить его лицензионные условия и совместимость с выбранным симулятором.
- **VT1 / VT2.** Использована общая модель NPN для функционального теста. Она не является проверенной моделью КТ3102ГМ и не доказывает гарантированное насыщение при заданном токе.
- **DA1 / КР1006ВИ1.** Генератор представлен парой управляемых ключей с порогами около 1/3 и 2/3 питания. Это идеализированный функциональный аналог 555, а не макромодель конкретной микросхемы.
- **HA1.** Излучатель заменён резистивной нагрузкой около 167 Ом, которая потребляет приблизительно 30 мА при включённом VT2. Реальная акустика, динамическое потребление и переходные процессы не моделируются.
- **HL1 / HL2 / VD1.** Используются общие приближённые модели диодов. Перед окончательным электрическим анализом их надо заменить моделями выбранных исполнений.
- **Источник питания.** Установлен идеальный источник 5 В. Просадка кабеля, внутреннее сопротивление адаптера, холодный запуск нагревателя и переходные процессы платы A1 не моделируются.

## Сопоставление частоты таймера

Для стандартной астабильной схемы 555:

[
t_H=0{,}693(R4+R5)C1
]

[
t_L=0{,}693R5C1
]

При R4 = R5 = 8,2 кОм и C1 = 4,7 мкФ ожидаются (t_Happrox53{,}4) мс, (t_Lapprox26{,}7) мс, (Tapprox80{,}1) мс и (fapprox12{,}48) Гц. Это несовместимо с частотой 1–2 Гц, указанной в статье. При C1 = 47 мкФ ожидаемая частота составляет около 1,25 Гц. В модели исходный номинал 4,7 мкФ сохранён, а 47 мкФ допускается только как отдельный сравнительный сценарий. Сначала необходимо проверить рисунок исходной схемы и подтвердить номинал, а не молча заменять его.

## Критерии первого прогона

1. При начальном низком сигнале S выход компаратора отпущен вверх, VT1 включён, `RESET` DA1 находится в низком состоянии, `OUT` таймера удерживается низким.
2. При росте S выше порога U2 стягивает `DOUT` вниз, VT1 закрывается, `RESET` поднимается, и на `OUT` появляются импульсы.
3. При снижении S ниже порога возврата U2 отпускает выход, VT1 снова удерживает RESET низким, генерация прекращается.
4. С `SOUND_ENABLE=1` VT2 должен следовать за импульсами OUT, а HL2 должен быть включён. С `SOUND_ENABLE=0` звуковая ветвь и HL2 должны быть выключены, но HL1 продолжает мигать.
5. Период OUT при C_TIMER = 4.7u должен быть близок к 80 мс, а при C_TIMER = 47u — близок к 0,80 с. Отклонения из-за модели и шага интегрирования нужно зафиксировать после реального запуска ngspice.
6. Пиковый ток из идеального источника является только сценарием по принятой модели нагрузки. Он не заменяет измерение полного модуля Amperka, включая нагреватель и холодный запуск.

**Статус проверки:** netlist создан, но результат симуляции пока не следует считать проверенным до запуска ngspice и просмотра сформированных временных рядов. Следующий этап — выполнение прогона, фиксация измерений и устранение ошибок модели, если они появятся.
