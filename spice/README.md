# SPICE-моделирование сигнализатора газа

Журнал текущего состояния: [`checkpoint_2026-10-25.md`](checkpoint_2026-10-25.md).

Каталог PNG-рисунков и приближённых схем: [docs/figures/README.md](../docs/figures/README.md).

## Первый этап: поведенческая модель

Файл `alarm_chain_behavioral.cir` моделирует цепочку:

`A1.S → U2 → DOUT' → R2 → VT1 → RESET DA1 → мигающий выход → HL1 / VT2 / HA1`.

В качестве симулятора выбран **ngspice**. Netlist самодостаточный и не требует внешних библиотек моделей. Сначала проверяем функциональную связность и ожидаемые тенденции. Позднее поведенческие блоки следует заменить моделями изготовителей и сравнить результаты.

### Установка и запуск

На CachyOS / Arch Linux установи ngspice и зависимости построителя графиков:

```sh
sudo pacman -S ngspice python-numpy python-matplotlib
```

Из корня репозитория запусти воспроизводимое сравнение двух сценариев:

```sh
sh spice/run_comparison.sh
```

Скрипт выполнит два прогона. Первый использует исходный C1 = 4,7 мкФ. Второй временно создаёт вариант с C1 = 47 мкФ и увеличенной длительностью входного сигнала. В основной netlist и номиналы проекта сценарий не вносит изменений. Период каждого варианта проверяется автоматически в ожидаемом диапазоне.

Результаты сохраняются в каталоге `spice/`:

- `ngspice.log` и `ngspice_47u.log` — логи симулятора.
- `spice_chain_results_4p7u.dat` и `spice_chain_results_47u.dat` — временные ряды обоих сценариев.
- `spice_chain_plots.png` — три графика для базового сценария.
- `spice_chain_results.dat` — временные ряды базового сценария, используемые построителем.

Можно запустить только исходный сценарий командой `ngspice -b spice/alarm_chain_behavioral.cir`, затем построить графики командой `python3 spice/plot_results.py`.

Параметр `SOUND_ENABLE=1` включает звуковой канал и HL2. Для проверки без звука поменяй его значение на `0` в netlist перед запуском.
 
## Ограничения модели

- **A1 / MQ-4.** Источник `VSENSE` создаёт синтетический аналоговый сигнал 0,30–4,50 В для проверки порога. Это не модель газового элемента и не калибровка напряжения в ppm.
- **U2 / TLV7041-Q1.** Поведенческий компаратор с открытым стоком и приближённым типовым гистерезисом. Это не официальная макромодель TI. TI публикует PSpice-модель TLV704x и модель TINA-TI для TLV7041-Q1 на странице продукта: https://www.ti.com/product/TLV7041-Q1. Следующим этапом следует получить исходный архив, проверить его лицензионные условия и совместимость с выбранным симулятором.
- **VT1 / VT2.** Использована общая модель NPN для функционального теста. Она не является проверенной моделью КТ3102ГМ и не доказывает гарантированное насыщение при заданном токе.
- **DA1 / КР1006ВИ1.** Генератор представлен парой управляемых ключей с порогами около 1/3 и 2/3 питания. Это идеализированный функциональный аналог 555, а не макромодель конкретной микросхемы.
- **HA1.** Излучатель заменён резистивной нагрузкой около 167 Ом, которая потребляет приблизительно 30 мА при включённом VT2. Реальная акустика, динамическое потребление и переходные процессы не моделируются.
- **HL1 / HL2 / VD1.** Используются общие приближённые модели диодов. Перед окончательным электрическим анализом их надо заменить моделями выбранных исполнений.
- **Источник питания.** Установлен идеальный источник 5 В. Просадка кабеля, внутреннее сопротивление адаптера, холодный запуск нагревателя и переходные процессы платы A1 не моделируются.

## Транзиентная модель с реальными моделями TI и MQ-4 делителем

Для сравнения с поведенческой моделью запускается отдельная цепочка в `alarm_chain_vendor.cir.in`. Она использует скачиваемую официальную модель TI TLV7041 для U2 и модель TI TLC555 в роли функционального аналога DA1. КТ3102ГМ заменён приближённой моделью 2N3904. Полная плата Amperka не имеет доступной SPICE-модели, поэтому вместо неё используется параметризованный резистивный делитель MQ-4.

Параметры сценарного делителя:

- $R_L=20\ \text{кОм}$, это значение использует библиотека Amperka TroykaMQ.
- $R_0=20\ \text{кОм}$ — пример номинального сопротивления сенсора при 1000 ppm CH₄. Это выбранное сценарное значение, не гарантия для конкретного экземпляра.
- $R_s/R_0=4{,}4$ в чистом воздухе, $1{,}0$ при 1000 ppm и $0{,}6$ при 5000 ppm. Значения основаны на коэффициенте из библиотеки Amperka и приближённых точках типовой кривой Hanwei MQ-4.

Ожидаемые напряжения делителя при 5 В:

| Сценарий | $R_s$ | Расчётное $U_S$ |
|---|---:|---:|
| Чистый воздух | 88 кОм | 0,926 В |
| 1000 ppm CH₄ | 20 кОм | 2,500 В |
| 5000 ppm CH₄ | 12 кОм | 3,125 В |

Эта таблица иллюстрирует выбранный параметрический сценарий и не является калибровочной характеристикой фактической платы. Порог P1 в vendor-тесте подстроен примерно к 2,4 В, чтобы проверить переключение около сценарной точки 1000 ppm. Реальная уставка требует калибровки сенсора.

Для загрузки официальных библиотек TI и запуска теста используй:

```sh
sh spice/run_vendor_model_test.sh
```

Скрипт скачивает архивы TI во временный каталог, включает PSpice-совместимость ngspice, запускает модель и проверяет напряжения S для чистого воздуха, 1000 ppm и 5000 ppm, а также состояние RESET. Создаётся `spice/vendor_chain_plots.png`. Исходные архивы производителя в Git не копируются.

## Сопоставление моделей при общем сигнале S

Для сравнения электронной цепочки без влияния различных моделей датчика запускается отдельный сценарий:

```sh
sh spice/run_model_comparison.sh
```

Скрипт использует один синтетический график напряжения S для поведенческой и vendor-модели, измеряет времена RESET, первый выходной фронт, установившийся период и средний ток на выбранных временных интервалах. Из узловых напряжений дополнительно рассчитываются токи HL1/R6, базовой ветви VT2/R9 и нагрузочного резистора RBZ. После базовых прогонов обе модели дополнительно запускаются с физически изменённым R9 = 588 Ом, чтобы проверить крайний допуск нагрузки выхода DA1. Нельзя рассчитывать worst-case как `(OUT − R9_N)/588` по ряду, полученному при R9 = 560 Ом, поскольку изменение резистора меняет нагрузку и сам уровень OUT. Вывод автоматической диагностики сохраняется в `spice/model_comparison_branch_summary.txt`.

`spice/model_comparison_overlay.png` показывает S, RESET, OUT и общий ток источника. `spice/model_comparison_branch_currents.png` показывает токи трёх нагрузочных ветвей. В проверенном сценарии высокий уровень OUT под нагрузкой составляет около 4,96 В в поведенческой модели и 3,80 В в модели TLC555. Из-за этого разность среднего тока тревоги порядка 11,2 % связана преимущественно с током HL1 и базовой ветви VT2, а не с нагрузкой RBZ. Это сравнение SPICE-моделей, не измерение аппаратуры.

Численные ряды и логи сохраняются в `spice/model_comparison_*.dat` и `spice/model_comparison_*.log`. Полные результаты и ограничения приведены в [`model_comparison_2026-10-25.md`](model_comparison_2026-10-25.md).

В успешном сравнительном прогоне RESET переключился с разностью порядка 16–18 мкс, а установившиеся периоды различались примерно на 0,1286 %. Средний ток в тревожном режиме различался примерно на 11,2 %. Это показывает близкую временную реакцию при различии оценок тока выходных каскадов. Значения относятся только к моделям. Они не подтверждают калибровку MQ-4, потребление всей платы AMP-B052 или соответствие пределу 300 мА.

Подробный протокол и все измеренные числа приведены в [`model_comparison_2026-10-25.md`](model_comparison_2026-10-25.md). Численные результаты и ограничения приведены в этом документе и в протоколе сравнения.


**Ограничения официальной модели TLC555.** Она совместима с ngspice 42 в режиме `set ngbehavior=ps`, но выдаёт предупреждения о нераспознанном параметре `lambda` в трёх MOS-моделях LEVEL=3. TLC555 — CMOS-аналог, а не электрически идентичный КР1006ВИ1. По этой причине абсолютные значения тока и гарантированные выходные уровни всё ещё требуют проверки.

## АЧХ и ФЧХ

Файл `sensor_bode.cir` выполняет AC-анализ в ngspice, а `plot_bode.py` формирует графики АЧХ и ФЧХ в четырёх панелях. Запускаются локально следующими командами:

```sh
ngspice -b spice/sensor_bode.cir
python3 spice/plot_bode.py
```

Результат — `spice/bode_linearized.png`, численные данные — `spice/bode_results.dat`.

**Важно о физическом смысле графиков.** Весь сигнализатор не является линейной стационарной системой. Газозависимое сопротивление MQ-4 меняется с концентрацией, U2 переключается с гистерезисом, а DA1 формирует автоколебания. Поэтому единой глобальной передаточной функции $H(j\omega)$ всей цепочки, которая однозначно описывает систему стандартными АЧХ и ФЧХ, нет.

В графики включены две группы линейных подсистем:

1. **Динамика MQ-4.** В руководстве Winsen MQ-4 v1.6 на рисунке Fig. 6 показан отклик при внесении датчика в газ и восстановление после удаления. Численные постоянные времени не заданы. Для ориентировочного Bode-прогона форма кривых приближена звеньями первого порядка с $\tau_{\mathrm{rise}}=2{,}2\ \text{с}$ и $\tau_{\mathrm{recovery}}=3{,}0\ \text{с}$, грубо оценёнными по рисунку. Это не паспортные характеристики, а иллюстративная аппроксимация. Источник: https://www.winsen-sensor.com/d/files/mq-4-%28ver1_6%29---manual.pdf.
2. **Времязадающая RC-цепь DA1.** Рассчитаны отдельные линейные состояния, когда переключатель разряда фиксирован. Для зарядного состояния $\tau_{\mathrm{ch}}=(R_4+R_5)C_1$, для разрядного $\tau_{\mathrm{dis}}=R_5C_1$. Эти кривые описывают RC-состояния отдельно, а не весь нелинейный астабильный генератор.

Таким образом, графики нужны для инженерного представления ограничений по быстродействию сенсорного канала и частотным характеристикам RC-участков. Для общего сигнализатора главным методом остаётся транзиентный анализ: порог срабатывания, задержка тревоги, период и скважность импульсов, восстановление и нагрузочные режимы.

## Сопоставление частоты таймера

Для стандартной астабильной схемы 555:

$$
t_H = 0.693(R_4+R_5)C_1
$$

$$
t_L = 0.693R_5C_1
$$

$$
T = t_H+t_L, \qquad f=\frac{1}{T}
$$

При $R_4=R_5=8{,}2\ \text{кОм}$ и $C_1=4{,}7\ \text{мкФ}$ ручной расчёт даёт $t_H\approx53{,}4\ \text{мс}$, $t_L\approx26{,}7\ \text{мс}$, $T\approx80{,}1\ \text{мс}$ и $f\approx12{,}48\ \text{Гц}$. Это несовместимо с частотой 1–2 Гц, указанной в статье. При $C_1=47\ \text{мкФ}$ ожидаемая частота составляет около 1,25 Гц. В модели исходный номинал 4,7 мкФ сохранён, а 47 мкФ допускается только как отдельный сравнительный сценарий. Сначала необходимо проверить рисунок исходной схемы и подтвердить номинал, а не молча заменять его.

### Первый прогон ngspice

Расчётный сценарий ранее выполнялся на ngspice 42. Базовый netlist прошёл расчёт и сохранил 30 113 строк временных рядов. После первой ошибки в распаковке массива NumPy исправлен скрипт построения графиков. Затем успешно выполнен автоматизированный прогон обоих сценариев.

| Измерение | C1 = 4,7 мкФ | C1 = 47 мкФ |
|---|---:|---:|
| Пусковой интервал OUT | 0,1114123 с | Не используется для сравнения установившегося режима |
| Установившийся период OUT | 0,08020065 с | 0,80167860 с |
| Частота, рассчитанная как 1/T | 12,4687 Гц | 1,2474 Гц |
| Пиковый ток моделируемой цепи | Около 65,5 мА | Не используется для оценки полного изделия |

Для базового сценария время подъёма RESET и первый фронт OUT находятся около 0,52070 с, что соответствует моменту пересечения синтетическим сигналом S порога U_REF. Для варианта 47 мкФ сигнал тревоги удерживался активным дольше, чтобы получить несколько полных периодов.

Результат подтверждает, что увеличение C1 в десять раз приблизительно увеличивает установившийся период в десять раз. Вариант с C1 = 47 мкФ даёт около 1,25 Гц, то есть соответствует текстовому упоминанию в статье диапазона 1–2 Гц. Это аргумент проверить номинал на исходном рисунке, но не основание менять номинал в проекте без подтверждения первоисточника.

Все значения относятся к **поведенческой** модели, а не к измеренному аппаратному устройству. Пиковый ток 65,5 мА относится только к смоделированной электронной цепи. Реальный ток платы A1 и её нагревателя не включён, поэтому этот результат нельзя сравнивать с требованием полного изделия ≤300 мА.

## Критерии первого прогона

1. При начальном низком сигнале S выход компаратора отпущен вверх, VT1 включён, `RESET` DA1 находится в низком состоянии, `OUT` таймера удерживается низким.
2. При росте S выше порога U2 стягивает `DOUT` вниз, VT1 закрывается, `RESET` поднимается, и на `OUT` появляются импульсы.
3. При снижении S ниже порога возврата U2 отпускает выход, VT1 снова удерживает RESET низким, генерация прекращается.
4. С `SOUND_ENABLE=1` VT2 должен следовать за импульсами OUT, а HL2 должен быть включён. С `SOUND_ENABLE=0` звуковая ветвь и HL2 должны быть выключены, но HL1 продолжает мигать.
5. После запуска различать первый пусковой интервал и установившийся период. При C_TIMER = 4.7u модель ожидает установившийся период около 80 мс. Для C_TIMER = 47u установить ожидаемый период около 0,80 с и подтвердить отдельным прогоном.
6. Пиковый ток источника относится только к моделируемой электронной цепи. Фактический ток модуля Amperka, включая нагреватель и холодный запуск, в netlist не задан и должен быть добавлен отдельной моделью или измерен.

**Статус проверки:** два сценария переходного анализа прошли успешно. Сравнение C1 = 4,7 мкФ и 47 мкФ проверено автоматическими критериями. AC-анализ сенсорной динамики и RC-состояний добавлен в `sensor_bode.cir`, а построение графиков — в `plot_bode.py`. Численный результат следует получать локальным запуском ngspice и строителя графиков. Перечень доступных официальных моделей и замен приведён в `model_inventory.md`.
